# Описание цели

Lo-Files — это файловый менеджер с дополнительными инструментами для работы с локальными файлами разных типов в одном приложении. Ценность для пользователя — в удобной системе хранения, просмотра, редактирования и быстрого доступа к файлам без необходимости переключаться между множеством отдельных приложений.

Помимо базовой работы с файлами и папками, в проекте предусмотрены вспомогательные инструменты: конвертеры, архиватор, а также сценарии использования приложения как музыкального плеера, аудиочиталки, редактора документов, презентаций и таблиц, и просмотрщика фото и видео. Создавая собственные папки, пользователь получает изолированное виртуальное хранилище и управляет им как своей структурой данных, а не системным деревом устройства.

## Стек и технические ограничения

### Клиент (мобильное приложение)

| Компонент | Технология |
|---|---|
| Фреймворк | Flutter / Dart |
| State management | Riverpod, включая `riverpod_generator` для кодогенерации провайдеров |
| Навигация | `go_router` |
| Локальная база данных | Drift поверх SQLite |
| Доступ к системным разрешениям | `permission_handler` |
| Аудио | `audioplayers` |
| Видео | `video_player` |
| SQLite-биндинги | `sqlite3_flutter_libs` |
| Архитектурный паттерн | Clean Architecture: `Presentation → Domain ← Data`, `Platform / Infrastructure` как отдельный слой |

Особенности проекта:
- Для MVP используется только локальное хранилище.
- Локальная БД реализуется на Drift поверх SQLite; Isar больше не используется.
- Доменные модели отделяются от storage-моделей, DTO и view-models.
- В проекте уже используются доменные сущности `File`, `Folder`, `User`, `RecentEntry`, `FavoriteEntry`.

### Domain vs Storage

В проекте явно разделены domain-модели и storage-модели:

- `File` → `LocalFiles`.
- `Folder` → `Folders`.
- `User` → `UserProfileCache`.
- `RecentEntry` → `RecentEntries`.
- `FavoriteEntry` → `Favorites`.

`UserProfileCache` используется как singleton-кэш локального профиля и гостевого режима.  
`File.extraMetadata`, `RecentEntry.syncStatus`, `FavoriteEntry.syncStatus` и `UserProfileCache.entitlementsCache` — это резервные поля под будущие расширения, но они не участвуют в MVP-бизнес-логике.

### Backend

Backend архитектурно спроектирован, но в MVP физически не реализуется. Это задел на будущее, а не рабочая часть текущей версии.

| Компонент | Технология |
|---|---|
| Фреймворк | NestJS |
| База данных | PostgreSQL с отдельной схемой на каждый модуль (`auth`, `users`, `billing`, `audit`) |
| Архитектурный паттерн | Modular Monolith с возможностью будущего перехода к микросервисам |
| Внутренние события backend'а | `@nestjs/event-emitter` |
| Будущая очередь сообщений | RabbitMQ / Kafka — только на уровне контрактов |
| Будущая монетизация | RevenueCat |

### Архитектурные механизмы

Это проектные механизмы, не сторонние библиотеки:

- **Event Bus** — реализуется поверх Riverpod и используется для событийного взаимодействия модулей без прямых зависимостей.
- **Viewer Registry** — реестр соответствий “формат файла → виджет просмотра”, чтобы новые форматы добавлялись без переписывания экрана просмотра.
- **File Action Registry** — реестр действий над файлами, из которого строится контекстное меню.
- **Screen Registry** — реестр маршрутов для будущих модулей-плагинов, встраиваемых в `go_router` без изменения существующей навигации.
- **EntitlementChecker** — интерфейс проверки прав на функции; в MVP это заглушка, возвращающая `false`.

## Требования для MVP

1. **Регистрация, авторизация и оффлайн-режим.**
   - В MVP backend-аутентификация не реализуется.
   - Пользователь может войти в приложение как гость без создания учётной записи.
   - Для этого используется локальная доменная модель `User` с полем `isGuest`.
   - Локальное состояние гостевого профиля хранится в `UserProfileCache`.

2. **Виртуальное файловое хранилище внутри приложения.**
   - Lo-Files создаёт собственное изолированное пространство для файлов и папок.
   - Пользователь видит структуру именно Lo-Files, а не весь системный корень устройства.
   - Источником данных в MVP выступает внутреннее локальное хранилище приложения; системные директории и внешние носители не входят в MVP.
   - Иерархия виртуального пространства строится через `Folders.parentId`, где `null` означает корень виртуального хранилища.

3. **Создание и управление папками.**
   - Создание новой папки в виртуальном хранилище.
   - Переименование папки.
   - Перемещение папок по структуре.
   - Удаление папок вместе с вложенными объектами при необходимости.

4. **Базовое управление файлами.**
   - Переименование файлов.
   - Перемещение файлов между папками.
   - Удаление файлов из виртуального хранилища.
   - По возможности — создание новых файлов поддерживаемых типов, если это не усложняет MVP.

5. **Поиск по имени и расширению.**
   - Поле поиска по имени файла.
   - Возможность учитывать расширение.
   - Поиск по части слова с нечувствительностью к точному совпадению.

6. **Просмотр базовых форматов: TXT, JPEG, PNG, MP3, MP4.**
   - Встроенный текстовый просмотрщик для TXT.
   - Встроенный просмотрщик изображений для JPEG и PNG.
   - Встроенный аудиоплеер для MP3.
   - Встроенный видеоплеер для MP4.
   - Открытие этих файлов без перехода в другие приложения.

7. **Экран «Недавние файлы».**
   - Автоматическое сохранение истории открытий.
   - Отображение списка недавно открытых файлов.
   - Полная очистка списка недавних в MVP.

8. **Экран «Избранное».**
   - Добавление файла в избранное.
   - Удаление файла из избранного.
   - Локальное хранение избранного без серверной синхронизации в MVP.

9. **Базовые настройки аккаунта и конфиденциальности.**
   - Редактор профиля с отображаемым именем.
   - Раздел «Конфиденциальность» с текстовой информацией о работе приложения с данными.
   - Настройки уведомлений-заглушек для будущих сценариев.
   - Управление доступом к внутреннему хранилищу через системные разрешения.

10. **Обработка ошибок, пустых состояний и неподдерживаемых форматов.**
   - Понятные сообщения об отсутствии доступа к памяти.
   - Сообщение о неподдерживаемом формате.
   - Сообщение о том, что файл слишком большой для текущей версии приложения.
   - Пустые состояния для главного экрана, недавних, избранного и поиска.

11. **Ограничение на открытие файлов размером более 1 ГБ.**
   - Файлы больше 1 ГБ могут отображаться в списке.
   - При попытке открытия приложение показывает сообщение, что файл слишком большой для текущей версии.

12. **Сохранение контекста последнего просмотра.**
   - При повторном запуске приложение может восстановить последний открытый каталог или файл.

13. **Автоматическая переиндексация каталога.**
   - При несоответствии локальной БД и фактического состояния файлов запускается переиндексация.
   - Приложение обновляет список и не оставляет “призрачных” записей.

## Информация о целевой аудитории

Lo-Files рассчитан на пользователей, которым важно держать файлы и медиа в одном месте и быстро получать доступ к нужному контенту. Это могут быть как любители структурированного хранения данных на своём устройстве, так и пользователи, которым нужен конкретный инструмент вроде удобного аудиоплеера, просмотрщика документов или менеджера файлов.

Основные группы аудитории:
- молодые и студенческие пользователи;
- взрослые пользователи, которым важны порядок и предсказуемость;
- люди, которые хотят заменить несколько отдельных приложений одним универсальным решением;
- пользователи, которым важно локальное хранение данных и контроль над своим хранилищем.
