## Описание цели
Приложение представляет из себя файлообменник с дополнительными функциями. Ценность для пользователя в удобной системе файлов самых разных форматов и их редактирования в одном приложении. Помимо системы работы с файлами, будут так-же ценится различные инструменты, например конвертор и архиватор. Lo-files можно будет использовать как музыкальный плеер или аудиочиталку, редактор документов, презентаций и таблиц, а так-же для работы с фото и видео файлами. Создавая различные пользовательские папки, пользователь станет полноправным хозяином своего хранилища.

## Стек и технические ограничения
### Клиент (мобильное приложение)
Компонент    Технология
Фреймворк    Flutter/Dart
State management    Riverpod (включая riverpod_generator для кодогенерации провайдеров)
Навигация    go_router
Локальная база данных    Drift (поверх SQLite), ранее использовался Isar — полностью заменён и возврата не планируется
Доступ к системным разрешениям    permission_handler
Аудио    audioplayers
Видео    video_player
SQLite-биндинги    sqlite3_flutter_libs
Архитектурный паттерн    Clean Architecture (Presentation → Domain ← Data, Platform/Infrastructure отдельным слоем)

### Backend (архитектурно спроектирован, но физически не реализуется в MVP)
Команда приняла решение не писать сервер на этапе MVP, поэтому это заложено только как архитектура на будущее, а не реальный работающий стек прямо сейчас.
Компонент    Технология
Фреймворк    NestJS
База данных    PostgreSQL, с отдельной схемой на каждый модуль (auth, users, billing, audit)
Архитектурный паттерн    Modular Monolith, спроектированный с возможностью будущего перехода к микросервисам
Внутренние события backend'а    @nestjs/event-emitter
Будущая очередь сообщений (не в MVP)    RabbitMQ/Kafka — только контракт данных проектируется совместимым
Будущая монетизация    RevenueCat (подписки, пожизненный тариф)

Архитектурные механизмы (специфичны для этого проекта, не сторонние библиотеки)
Event Bus — реализован поверх Riverpod (StreamController/StreamProvider) для событийного взаимодействия модулей без прямых зависимостей.
Viewer Registry — реестр "формат файла → виджет просмотра", позволяющий добавлять новые форматы без изменения кода экрана просмотра.
File Action Registry — реестр действий над файлом (переименовать, удалить и т.д.), строит контекстное меню динамически.
Screen Registry — реестр маршрутов для будущих модулей-плагинов, встраиваемых в go_router без правки существующей навигации.
EntitlementChecker — интерфейс проверки прав на функции (в MVP — заглушка, всегда возвращающая false).

## Требования для MVP
1.Регистрация, авторизация и оффлайн режим.
- прописанные функции, но на них заглушки, бэкенда нет, переход на главный экран по одной кнопке, без создания учетной записи
2.Виртуальное файловое хранилище внутри приложения.
- Lo-Files создаёт «своё» пространство для файлов и папок, не опираясь напрямую на системный файловый менеджер.
- Пользователь видит структуру папок и файлов именно Lo-Files, а не весь системный корень устройства.
- В качестве источника используется внутренняя память; внешние носители и системные директории не входят в MVP.
3.Создание и управление папками.
- Создание новой папки в виртуальном хранилище.
- Переименование папки.
- Перемещение папок по структуре.
- Удаление папок вместе с вложенными объектами (с понятным предупреждением, если это необходимо).
4.Базовое управление файлами.
- Переименование файлов.
- Перемещение файлов между папками.
- Удаление файлов из виртуального хранилища.
- По возможности – создание новых файлов поддерживаемых типов (например, пустой TXT) в рамках MVP, если это не перегружает реализацию.
5.Поиск по имени и расширению.
- Поле поиска по имени файла.
- Возможность учитывать расширение (например, искать только TXT или только MP3 при указании части названия и/или фильтра).
- Поиск по части слова с нечувствительностью к полному совпадению (ввод «консп» должен находить «Конспект по алгебре.txt»).
6.Просмотр базовых форматов: TXT, JPEG, PNG, MP3, MP4.
- Встроенный текстовый просмотрщик для TXT.
- Встроенный просмотрщик изображений для JPEG и PNG.
- Встроенный аудиоплеер для MP3.
- Встроенный видеоплеер для MP4.
- Открытие этих файлов без необходимости переходить в другие приложения, с базовыми контролами (пауза/проигрывание, перелистывание, масштабирование изображений и т. п.).
7.Экран «Недавние файлы».
- Автоматическое сохранение истории открытий.
- Отображение списка недавно открытых файлов с возможностью перейти к ним.
- Функция полной очистки списка недавних (удалить все записи), без частичной очистки отдельных элементов в MVP.
8.Экран «Избранное».
- Добавление файла в избранное (например, через контекстное меню или кнопку на экране просмотра).
- Удаление файла из избранного.
- Локальное хранение состояния избранного, без синхронизации с сервером или облаком на этапе MVP.
9.Базовые настройки аккаунта и конфиденциальности.
- Редактор профиля (изменение отображаемого имени, возможно аватар, если это решено на уровне дизайна).
- Раздел «Конфиденциальность» с текстовой информацией о том, как приложение работает с данными (без сложных переключателей на старте).
- Настройки уведомлений с заглушками для будущих сценариев (уведомления о синхронизации, уведомления о расширениях), которые в MVP не активны.
- Управление доступом к внутреннему хранилищу: проверка разрешений ОС, понятное сообщение при их отсутствии.
10.Обработка ошибок, пустых состояний и неподдерживаемых форматов.
- Понятные сообщения: «нет доступа к памяти, включите разрешения в настройках», «формат пока не поддерживается», «файл слишком большой для текущей версии приложения».
- Пустые состояния для главного экрана, недавних, избранного, результатов поиска (например, «здесь пока нет файлов, добавьте первый»).
- Отсутствие тихих сбоев (silent failure) в ключевых сценариях.
11.Ограничение на открытие файлов размером более 1 ГБ.
- Файлы >1 ГБ могут отображаться в списке, но при попытке открыть приложение показывает сообщение «файл слишком большой для текущей версии приложения», не пытаясь загрузить его полностью.
12.Сохранение контекста последнего просмотра.
При повторном запуске приложение может восстановить последний открытый каталог или файл, чтобы пользователь мог быстро продолжить работу.
13.Автоматическая переиндексация каталога.
При обнаружении несоответствия между локальной БД и фактическим состоянием файлов (например, если файл исчез или изменился внешним образом) Lo-Files запускает переиндексацию и обновляет список, не оставляя «призрачных» записей.

## Информация о целевой аудитории и прочая социалка
Приложение будет комфортным инструментом для разных групп пользователей. От любителей структурированной системы на своём устройстве, до пользователей которые хотят решить конкретную проблему - например найти хороший аудиоплеер. Ставка идёт как на молодую/студенческую аудиторию, так и на старшее пунктуальное поколение.
